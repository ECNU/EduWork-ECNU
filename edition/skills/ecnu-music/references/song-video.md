# 歌曲视频：音频、歌词时间轴与 Remotion

只在用户要求歌曲视频时采用本流程。先用现有 HTML 的“自动浏览”预览阅读效果，见 [song-timeline.md](song-timeline.md)。默认使用同一原音频、完整歌词、背景和时间模型；视频制作不触发重新生成歌曲。现有视频工具负责项目、运行时与编码，不修改宿主 HTML 预览或重新安装 Remotion。

## 默认：完整歌词自动浏览

视频不能让观众手动滚动，所以让完整歌词在固定的可视窗口内缓慢向上移动。复用作品目录 `song-timeline.js` 的 `sampleReading(frame / fps * 1000, durationMs).progress`，乘以实际排版后的溢出高度作为负向 Y 偏移。开始和结尾各停留最多 5 秒；没有溢出时保持静止。背景、标题与进度固定，当前页歌词保持足够字号。根据最终画幅测量歌词高度，不能直接套用桌面页面的像素值。

这是阅读进度，不是唱词时间戳；不生成虚假的 SRT/LRC 或宣称逐句同步。先检查首、中、尾帧、换行、最后一句完整可见和原音轨完整播放。无需 ASR 或人工逐句校时，用户明确要跟随唱词/卡拉 OK 时再走下面的同步分支。

## 可选：唱词同步时先核实对齐条件

输入必须属于同一版本：实际歌曲音频、原始歌词和针对这份音频的时间轴。保留输入路径、音频 SHA-256、时间轴来源与核对状态；换音轨、剪裁或变速后重新核对。

可用时间轴来源是用户确认的 LRC/SRT/字幕 JSON，或实际音频分析得到并核对的时间戳。收到旧字幕时仍需核对音轨版本及开头、中间、结尾，不能仅凭文件扩展名认为可靠。

没有时间轴时先用 `speech_transcription_providers` 查看当前就绪提供方及 `timestamps` 能力。有合适提供方时调用 `speech_transcribe`，传真实音频、提供方与语言。返回的分段时间戳只是候选：核对唱词覆盖、段落顺序、重复副歌、前奏/间奏、长音及结尾。保留原歌词，不用错误识别文本覆盖原作；也不能把多句识别结果的总时间均分给原歌词后称为精准对齐。

当前 `speech_transcribe` 不提供“传入原歌词做强制对齐”的参数。仅返回文本、漏掉大段歌词或时间戳失真时，应说明仍需对齐能力或经过校对的字幕。原生工具未提供对齐入口时，不编造工具名，也不自动下载大模型、读取凭据或改用外部上传服务。需要新增提供方时单独明确接入方案。

同步模式把经过核对的字幕保存在 HTML 导出的 `timeline.json` 的 `lyrics.cues`，格式兼容 Remotion `Caption[]`：每条含 `text`、`startMs`、`endMs`、`timestampMs`、`confidence`；未知后两项填 `null`。时间相对完整源音频起点，单位毫秒，须有穷、非负、有序、不重叠、结束晚于开始且不超音频时长。首版按句显示；只有字级时间戳真实存在且经核对时才做逐字高亮。前奏和间奏留空，进度条照常推进。合唱重叠声部需选择明确的主唱词显示轨，不能把同时演唱的内容强行排成先后。

## 复用现有可编辑视频工程

读取当前环境的 `artifact-video` 技能及其规格。使用 `video_project` 的 `init` 创建唯一工程，通过 `stage` 把原音频和可选背景图放到工程 `public/`，保留原文件。用现有编辑工具修改工程 `src/`，新增字幕 JSON，并保留 runner 约定的组合入口和计划结构；不把整首歌拆成 TTS 旁白，不调用 `speech_synthesize` 重唱歌词。

默认 `9:16`、`1080×1920`、30 fps；用户指定横屏时遵从。一个静态背景即可，用户没提供图时可用纯色或简单渐变，无需自动生图。保留手机界面遮挡所需的上下安全区；默认完整歌词列表自动浏览；同步模式才突出当前句、弱化前后句。长句允许换行，避免缩成小字。画面可显示曲名、歌词和时间/进度，不添加复杂粒子、分镜或旁白。

用真实音频时长确定工程总帧数和进度，按现有 runner 的无旁白场景长度限制组织计划。源音轨作为唯一主音轨，完整播放一次、原速、正常音量；不要将其套用默认 BGM 的循环、压低音量或配音 ducking。素材用 `staticFile()`；复制作品目录的 `song-timeline.js` 到工程，默认用 `sampleReading`；同步模式才另复制已核对的 `timeline.json` 并用 `sampleTimeline(timeline, useCurrentFrame() / fps * 1000)` 驱动画面，避免 CSS animation 和计时器。沿用 HTML 已确认的背景、歌词排布与进度；不录屏、不播放浏览器音频后猜渲染进度。没有歌词的区间不高亮任何一句。当前插件尚未提供一键歌曲视频适配器，需按现有可编辑视频工具完成场景与编码。

调用 `validate` 后再 `render`，交付 H.264/AAC MP4 和封面；同步模式另附真实字幕 JSON/SRT（已有 LRC 时一并保留）。视频渲染成功只证明编码完成；自动浏览模式检查整份歌词从头到尾可读、末句停留和音轨完整；同步模式另逐段核对唱词时机，检查首句、间奏、重复副歌与末句。两种模式都确认没有整曲截断或音频循环。遵循 Host 的 `present` 入口登记实际文件。

## 乐谱跟随：可选实验

生成阶段的 ABC 是音乐计划，其速度和小节可用于理解结构，不能直接视为最终录音时间轴。谱面播放器按 ABC 合成音频时的高亮，不代表它与 YuE2 成品歌声同步。

用户要求乐谱跟随时，可沿用已有转谱结果；或在用户授权的完整流程中对最终音轨调用 `ecnu_music_submit` 的 `transcribe`，再查询、下载实际 ABC、MIDI 与 `events.json`。服务支持转谱产物不等于每个任务都存在这些文件，以 artifacts 列表为准。

带时刻的事件能作为小节/旋律定位的候选，但仍需把事件映射到这次转谱的谱面元素并校验。先验证小节高亮或当前谱行，逐音符跟随作为后续实验。若用户要跟随原始生成谱，还需额外对齐原谱与实际演奏；不能直接复用转谱的索引。没有经校验的映射时交付静态谱面，不宣称同步。
