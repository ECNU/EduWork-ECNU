# 音乐提示词、歌词与输入回显

构建或修改音乐输入时使用本指南；已有任务的查询、下载和排谱无需重新编写提示词。只要求提示词时交付文本，不提交生成。线上执行继续使用 `ecnu_music_*` 与学校登录，工具字段以 [workflows.md](workflows.md) 和当前能力为准。

## 先判断哪些信息需要补充

从当前对话、用户附件和明确选中的旧作品回执提取：原创还是改编、演唱语言、主要曲风、独唱/对唱/合唱、核心配器、速度与情绪、歌词来源、必须保留的旋律或文字。区分用户要求与自行补充，不把风格示例变成用户偏好。

| 情况 | 处理 |
| --- | --- |
| “改编这首”，但保留旋律还是只保留歌词不明 | 先问保留目标，再选音频翻唱或新创作；明确指定翻唱并给出原曲时不重复问 |
| 必须保留的原音频、歌词或 ABC 缺失 | 先查上下文和已选作品记录；找不到再请用户补充，等待后再提交 |
| 风格/人声等未定，且不同选择会明显改变用途 | 简短问关键选择，例如典礼用庄严合唱还是宣传用青春流行 |
| “全程男声独唱”同时要求“副歌混声合唱”，未说明取舍 | 指出具体冲突并询问；若用户明确要求分段变化，则保留变化 |
| 创作方向清楚，只缺 BPM、调性或次要乐器 | 可留给模型或作合理选择并说明，不要求用户补专业参数 |
| 用户已授权根据主题原创歌词 | 可以拟词；若要求先看稿，先交稿并等待反馈 |

一次集中问最影响结果的一至三个问题，避免逐项填表。关键问题未回答时可以整理已知内容，不猜答案提交。已有男声、粤语等要求却生成不符，属于执行效果问题，不能再称用户没提供信息。

## 编写 style

默认以英文音乐描述组织 `style`，中文说明帮助用户核对；歌词不翻成英文。用户提供完整提示词时保留其全部实质要求；要求原样提交或指定提示词语言时原样遵从。需要改写时展示改写后的实际内容与关键变化，不默默省去难满足的要求。

优先表达：**演唱语言 → 主风格 → 人声形式与特征 → 主要乐器 → 速度/律动 → 情绪与必要编曲变化**。这是组织顺序，不要求每项都有值。用清楚的短句或逗号分隔描述；没有官方最佳词数，不为了简短而删掉明确约束，也不靠重复禁止词加强控制。

- 先确定主要音乐方向，少量补充兼容元素；复杂的段落变化按出现顺序描述，检查与歌词标签、已有 ABC 是否一致。
- 用可听辨的特征描述参考作品，如低沉男声、钢琴主导、克制的鼓与渐入弦乐；仅靠歌手或歌名不能表达完整编曲需求，也不承诺复制声线。
- 限制项可以简洁保留，但没有独立 `negative_prompt` 字段；“不要女声”等文字不构成硬约束。连续失败时核对实际请求和结果，不无止境堆叠否定词。
- BPM、人声音域、SATB 等写在 `style` 中是目标；接口没有独立 BPM 锁、声线克隆或逐段歌手身份参数。已有 ABC 的拍号、速度与目标冲突时，应解释并按用户授权修改谱或确认取舍。
- `cot`、`seed`、`cfg_scale` 等放在对应参数中，不混进歌词或用提示词假装提供接口没有的功能。默认参数规则见工作流；seed 默认省略，由服务随机生成，用户指定则保留，包括 0。

例如用户已明确要粤语、低沉男声、钢琴抒情、约 78 BPM 和克制的弦乐渐强，可以写：

```text
Cantonese piano ballad, solo adult male baritone with a warm low register and a slightly husky tone, clear Cantonese diction. Piano arpeggios lead the arrangement, with restrained bass and soft drums. Around 78 BPM, 4/4, intimate verses and a gradual string build in the chorus, ending with a quiet piano outro.
```

这只是原创输入示例，不是已验证的最佳配方；不能把示例里的音色、速度或乐器带入无关任务。普通创作不为验证提示词自动增加候选、固定 seed 或调整 CFG；对照试验按用户授权执行。

## 检查歌词与长度

`lyrics` 放实际唱词及段落标签，编曲说明放进 `style`。新拟歌词可用 `[Verse]`、`[Pre-Chorus]`、`[Chorus]`、`[Bridge]`、`[Outro]`，段落之间空行；不要将“副歌重复两遍”等编辑说明当作唱词。用户已有歌词、重复次数和顺序须保留；调整其措辞、删节或结构需有明确授权，保留原版。

检查是否存在过长而难换气的单句、段落边界不清、速度与唱词密度明显冲突；说明具体问题与建议。已有旋律的换词或翻译还需匹配乐句、音节、重音与换气位置，不能仅按总字数判断。字数或段落数不直接换算成确定时长。

官方资料没有给出统一的最佳中文歌词字数、每句字数或最多段落数。不要自行设置“超过 300 字/32 行就裁剪”等规则；也不要把服务 `lyrics` 的 16000 字符上限理解为质量保证。输入超出实际接口限制时说明限制，请用户选择缩减范围或另一方案，不默默截断或拆成多次付费生成。

官方《今晚不眠》示例约 391 个汉字、44 行非空唱词，模型页标注 3:24，说明完整多段歌词是有效使用场景；这不是最佳长度阈值，也不能保证同规模歌词都能完整唱出。长歌词先检查结构与实际生成预算。完成后分别检查 ABC/semantic 的 `truncated`、实际时长与结尾，以及可用的试听或歌词核对；无截断标记不证明没有漏唱，无法核对时如实说明。用户给定完整长歌词时按授权保留，不为改善指标自行缩短。

## 实际输入回显

生成前用简短中文说明将采用的方向与自行补充之处；信息充分且用户已要求生成时直接推进，不新增固定审批步骤。仅拟稿时明确是拟用输入，不能标成实际提交。

生成、规划或翻唱交付时，正文包含以下信息，不只藏在附件或 HTML 中：

1. **完整实际 `style`**：从本次 `receiptPath` 指向的 `request-*.json` 的 `input.style` 读取，或通过 `ecnu_music_library` 找到相同 `request_id` 的输入；按原文代码块输出，并附简短中文说明。已提交的中文提示词也原文输出，不事后替换成英文。
2. **实际歌词与版本**：以同一回执的 `input.lyrics` 为准。本轮正文没有完整展示时给出全文；本轮已经展示且逐字相同时明确沿用该稿。历史消息中出现过、内容有变化或版本不明时仍需展示实际文本，不凭印象声称未改。
3. **参数与来源**：操作、请求的模型标识、适用的 `cot`/`n`、seed、`cfg_scale`、参考音频或 ABC 的来源，以及 request/job ID。`title` 是本地标题，不能称作模型提示词。ABC 条件生成说明使用哪份谱，完整 ABC 可作为附件。
4. **实际结果**：成功/失败、候选对应的任务 ID、截断情况及已做的检查。音频/乐谱路径沿用真实工具返回。`n=2` 的回显对应共享请求，结果与实际 seed 按候选分别列出。

参数说明要区分三类：请求里已提交的值；服务返回的实际值；未返回的未知值。例如省略 seed 写“未传入，由服务随机生成”，返回后再补实际 seed；未传 `cfg_scale` 写“服务默认，实际值未返回”，不能自行填 1.0。`model=ecnu-music` 是请求标识，不足以证明底层权重、解码器或配置版本；只报告服务实际披露的身份。大整数 seed 保留精确十进制字符串，不取整或承诺跨运行环境逐字节复现。

`cover` 请求不接受 `cot`/`n`，`transcribe` 不接受风格、歌词或 seed；不要为凑表格补不存在的参数。转谱交付只说明适用的音频来源、mode 与结果。旧回执缺字段或服务未返回配置时明确缺失，不通过重新生成来补记录。回显只选择上述创作字段，不整份转发带内部绑定信息的回执，不输出凭据。

作品页若传入 `style`，使用同候选回执中的原文；中文解释放在正文。现有导出工具没有完整参数字段，不能把整份 JSON 塞入 `style` 或声称网页已展示全部参数。提示词表达的是目标，是否实现需要结果证据。
